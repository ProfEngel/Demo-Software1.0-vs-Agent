Phase 1: Software 1.0

Erstellung der barrierefreien Offline-PWA

Aufbau einer komplett lokalen, browserbasierten Lern-Webapp (Progressive Web App) für Studierende ohne Vorkenntnisse über Grundlagen von Software 1.0, Chatbots und KI-Agenten.

Highlights & Architektur:
  • Zero Cloud / Zero API: Reine Software 1.0, kein LLM-Backbone, keine Tracker oder externe CDNs.
  • Deterministischer Freitext-Vergleich: Exakter Zeichenvergleich. Bei Differenz lautet die Rückmeldung neutral: „nicht exakt gleich – Bedeutung selbst prüfen“ (kein pauschales Falsch-Urteil).
  • PWA & Datenschutz: Lokaler Service Worker (Offline-first), 10 Kern-Lernkarten, Datenhaltung rein im Browser (`localStorage`), sicherer JSON-Export/-Import mit Schemaprüfung.
Baue im freigegebenen Projektordner eine kleine deutschsprachige PWA „KI-Superkraft – mein Lernsystem“. Thema dieses Vortrags: Software 1.0, Chatbot, Agentic AI, Prompt, Harness, Tools, Skills, Memory und menschliche Prüfung. Zielgruppe: Studierende ohne IT-Vorkenntnisse. Zuerst reine Software 1.0, KEIN Modellaufruf und keine API. Zehn fachlich korrekte Lernkarten, kurze Zuordnungsfragen mit begründeten Lösungen, Lernen/nochmals üben, Fortschritt, eigene Karten und Notizen. Eine Freitextaufgabe vergleicht bewusst nur die exakte Zeichenfolge und sagt bei Abweichung „nicht exakt gleich – Bedeutung selbst prüfen“, niemals „fachlich falsch“. Musterlösung: „Ein Agent wählt erlaubte Werkzeuge und prüft ihre Ergebnisse.“ Design: ruhig, klar und einfach; Creme #F7F7F5, Petrol #24666A, Salbei #DCEFE1, dunkle Schrift #182C33. Keine Textwüsten, Tracker oder CDN. Technik: mehrere lokale Dateien, relative Pfade, Manifest mit Icons, versionierter Service Worker. Nach dem ersten vollständigen Laden offline lauffähig. Daten nur lokal, schema- und größenvalidierter JSON-Export/-Import, Reset nur nach Bestätigung. Keine Secrets. Gib Start- und Installationsanleitung.

Phase 2: Agentic AI

Initialisierung des modelagnostischen Agenten „Hugo“

Aufbau einer separaten Entwicklungsumgebung für den ersten agentischen Lerncoach „Hugo“ mit festen Sicherheitsgrenzen und deterministischen Werkzeugen. Die Offline-PWA bleibt unangetastet.

Highlights & Leitplanken:
  • Zero Trust Sandbox: Kein Betriebssystem-Shell-Zugriff, keine offenen Netzwerk-Sockets für den Agenten.
  • Exakt 4 deterministische Tools: `get_card` (Karten laden), `search_memory` (SQLite-Memory abfragen), `update_progress` (Fortschritt belegen), `clarify_question` (gezielte Rückfrage).
  • Verhaltenskodex (`AGENTS.md`) & Skills (`SKILL.md`): Fortschritt darf nur bei nachvollziehbarer Evidenz verbucht werden. Wiederholungen zählen nicht doppelt. Human-in-the-Loop vor kritischen Aktionen.
  • Automatisierte Test-Suite: 5 Testfälle gegen Prompt Injections, fehlerhafte Tools und Ambiguitäten.
Arbeite in einer separaten Kopie der KI-Lernwerkstatt. Die reine Offline-PWA bleibt unverändert. Baue einen kleinen modelagnostischen Agenten „Hugo“, nutzbar im Harness-Chat/CLI und optional über lokale HTML-UI. Der erste Agent erscheint bereits als Kachel in einem kleinen Hub. Keine schöne UI als Agent ausgeben. Auftrag: Lernantworten zu Software 1.0, Chatbot und Agent verstehen; freigegebenes Memory vor jeder Beurteilung nachschlagen; bei Unsicherheit rückfragen; nur bei belegter richtiger Antwort erlaubten Fortschritt markieren und danach kontrollieren. Regeln kurz in AGENTS.md, Vorgehen als Skill; deterministische Werkzeuge für Karten, Memory und Fortschritt. Maximal vier Tools je Auftrag, höchstens eine Rückfrage, kein Shell-/Netzwerkzugriff für den Laufzeitagenten. Modell austauschbar, kleinere Modelle erst nach denselben Tests zulassen. Nutze material/agent/coach.py als lokal begrenztes Werkzeug und dessen SQLite-Memory. Browserdaten sind NICHT automatisch im Harness: nur expliziter validierter Import/Export mit Freigabe; eine Datenwahrheit je Ausbaustand. Keine API-Schlüssel in Browser, Git oder localStorage; für echte Modellaufrufe den vorhandenen Harness nutzen. Eine Schrittanimation muss als Simulation gekennzeichnet sein. Zeige Tool-Protokoll und prüfe die fünf Fallaufgaben plus Wiederholung: richtige Paraphrase, Teilantwort → Rückfrage, falsche Antwort → nicht abschließen, Prompt-Injection → keine zusätzlichen Rechte, ungültige Tooldaten → keine Änderung; Wiederholung zählt nicht doppelt. Vor Senden, Löschen, Veröffentlichung oder Zugriff auf private Daten immer stoppen und fragen.

Phase 2: Agentic AI

Interaktiver Agenten-Hub & Harness-Bereitstellung

Bereitstellung des Agenten Hugo über einen interaktiven Hub (`hub/index.html`) sowie den Antigravity-Harness, inklusive Live-Visualisierung des Tool-Protokolls.

Highlights:
  • UI-Ehrlichkeit: Transparente Kennzeichnung, dass die UI nur eine Schnittstelle ist und Schrittanimationen reine Simulationen darstellen.
  • Modell-Kopplung: Anbindung über das lokale Modell via Antigravity Harness (ohne Secrets im Frontend).
  • Sichere Bereitstellung: Lokaler Hub auf separatem Port getrennt von der Software 1.0 PWA.

Phase 2: IT-Sicherheit & Metapher

Sicherheits-Audit & Erklärung der „Sandbox“

Umfassende Sicherheitsanalyse des erzeugten Codes und kindgerechte Erklärung des Sandboxing-Konzepts zur Verhinderung unbefugter Systemeingriffe.

Highlights des Sicherheitschecks:
  • Zero System Access: Hugo hat keinen Zugriff auf PowerShell, Terminal, `subprocess` oder Netzwerk-Sockets.
  • Metapher: Der Agent sitzt wie ein Kind in einem sicheren Sandkasten (Sandbox) im Wohnzimmer: Selbst wenn er mit Sand wirft, bleibt das Wohnzimmer (das Betriebssystem) unberührt.
